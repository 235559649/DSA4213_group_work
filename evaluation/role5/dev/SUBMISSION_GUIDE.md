# GitHub 精简版提交说明

本目录是独立新建的精简提交版；原 `role5-github-ready-20261028` 目录保持不动。工具、使用说明、示例和测试使用英文，三份报告保留中文。本次没有上传 GitHub。

## 提交哪些内容

建议将本目录整体放入项目仓库的新路径，例如 `evaluation/role5/`，保留内部相对路径。提交工具、测试、小示例、三份报告、results 汇总、运行配置、官方结果、补丁、实际候选、计时及证据索引。隐藏文件 `.gitignore` 和 `.gitattributes` 也要保留。

这里覆盖全部 76 次执行、63 次入选运行、8 道不同开发题；没有按结果好坏筛掉运行。保留的官方日志可能受仓库上层 `*.log` 规则影响，提交前检查它们确实被纳入。

## 单独保存哪些内容

完整证据位于相邻的 `role5-evidence-archive-20261028/role5-full-evidence-20261028.zip`，另有 ZIP 哈希清单。此 ZIP 不放进日常代码目录；以后可作为 Release 附件或课程允许的共享材料交付。

大体积的完整轨迹、初始排名、D 事件、D 排名快照和官方测试全文只在归档中保留。归档还包含所有小体积证据，可独立作为完整评价输入。原完整目录、ZIP 以及精简目录是三个独立产物。

## 怎样查看与复算

- 只取得 GitHub 精简版：可读三份报告、查看官方结果/补丁/汇总、运行 30 项基础测试和合成示例。
- 取得完整证据：先校验 ZIP，解压到独立目录，再用英文工具读取解压目录中的 manifest，复算全部真实实验指标并运行 5 项集成测试。
- 默认发现所有测试时，未指定完整证据的 5 项集成测试会明确跳过，不能把跳过写成通过。

具体命令见 [完整证据说明](docs/FULL_EVIDENCE.md)。不要往原完整目录或精简版中覆盖解压。

## 链接与交付边界

小证据保持本地相对链接；大证据链接转到归档索引，给出准确成员路径和哈希。当前 ZIP 仅在本地准备好，没有真实在线下载地址。将来向老师交付仓库时，还需提供可访问的归档，并在 `evidence/ARCHIVE.json` 的 download_url 和英文说明中填入真实地址。

精简版和完整归档使用独立校验清单，不能互换。预计算 results 没有变成“仅凭精简证据可完全复现”的结果；完整复算仍需要归档。报告中的 D 耗时、失败分析和跨轮比较边界保持不变。

这仍是角色 5 的预实验交付部分。小组最终还要整合 proposal、最终报告（含贡献声明）与 presentation，不能把开发题结果称作独立留出集验证。

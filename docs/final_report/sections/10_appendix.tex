\subsection*{A.3 Swing tasks}
The main-round ranking of the four conditions is decided by these seven tasks, since the other 33
have the same outcome in every condition. Two patterns stand out. First, the usual way to lose a swing
task is a regression rather than a wrong location: four of \condA's six losses are F4, where the target
tests pass but existing tests break. Second, the hint is neither necessary nor sufficient. In
sphinx-7757 the reference file is outside every hint (rank 97/110), yet \condC{} fixed it; in
sympy-18698 the file is ranked first in every hint, yet only \condA{} fixed it.

\subsection*{A.5 Stability: 8 tasks $\times$ 3 rounds}
Eight tasks were drawn before any result was seen and run three times per condition (round 1 is
the main round). Two tasks were never solved and one was always solved, so the variation comes from
the other five. Even a task solved by every condition in the main round can fail later:
sympy-24443 was resolved in round 1 everywhere, but \condB{} and \condC{} solved it only once in three
rounds. Over 24 runs per condition the totals differ by at most three (\condA{} 14 to \condD{} 17),
which is the same size as the main-round differences, so we do not rank the conditions on either
round alone. The one consistent direction is pytest-10081, which \condC{} and \condD{} solved in all three
rounds and \condA{} in one.

The 15 messages reached ten runs; 37 of 52 candidate events were withheld. A run can
generate multiple events and receive multiple messages. Among runs with feedback, nine had the same
repair outcome as \condC{} and one was \condC{}-only (\texttt{django-14311}, diagnostic
note only). Among the 30 runs without feedback, 27 matched \condC{} and three were
\condC{}-only. Receipt of feedback is selected by the agent's trajectory, not randomized,
so neither comparison estimates a causal effect. Setup-related candidate events can be
filtered out even though no final unresolved run was assigned F5.


Of 37 withheld events, 12 had unclear source locations; weak signal, printed source,
route limits and environment errors accounted for five each, and other reasons for five.

\begin{samepage}
\paragraph{Failure case: \texttt{django-13590}.}
Named tuples passed to \texttt{\_\_range} crashed after a Django 3.0 upgrade. All conditions
edited the same line in \texttt{django/db/models/sql/query.py} as the official fix.
Expanding resolved elements as positional arguments to \texttt{type(value)} repaired the
named-tuple case but broke ordinary \texttt{list} and \texttt{tuple} construction, leaving
140--144 of 145 existing tests passing. This was coded F4 for every condition despite
successful file and line localization.

\end{samepage}
\begin{samepage}
\paragraph{Structure case: \texttt{django-16950}.}
The issue concerned an admin inline formset ignoring a UUIDField default. Structural
fusion moved \texttt{django/forms/models.py} from rank 35 in $L$ (outside \condB{}'s hint)
to 19 in \condC{} (inside). \condC{} opened it at model call 1 rather than \condB{}'s
call 2, using about 62k versus 127k tokens; both resolved the task. \condA{} and \condD{}
also reached the file but broke three inline-default tests (F4). This supports a concrete
navigation improvement while leaving the downstream patch-quality mechanism unresolved.

\end{samepage}
\paragraph{Feedback case: \texttt{sympy-18189}.}
The issue reported incomplete \texttt{diophantine()} results depending on symbol order
with \texttt{permute=True}. After an agent edit, execution produced the following
traceback excerpt (intermediate frames omitted; presentation slide 15):
\begin{quote}\small\ttfamily\raggedright
File "sympy/solvers/diophantine.py", line 185\\
\hspace*{1em}[Previous line repeated 989 more times]\\
File "sympy/core/expr.py", line 126, \_\_eq\_\_\\
File "sympy/core/sympify.py", line 265\\
RecursionError: maximum recursion depth exceeded
\end{quote}
Fusion promoted \texttt{diophantine.py} from rank 2 to 1; the deepest-frame file,
\texttt{sympify.py}, remained outside the hint. Traceback proximity does not establish
the root cause of the original defect.
\condD{} resolved the task, as did \condA{}--\condC{}, so the rank improvement did not
demonstrate an additional repair. Among the other four first-feedback reranks,
\texttt{sympy-20428}'s first reference file stayed at rank 341 (F3), while the other three
stayed at rank 1 and resolved. The online pipeline had no reference-file labels; these
before/after comparisons were made only during offline evaluation.

\subsection*{A.7 Results by repository}
Gains do not follow ranking quality. SymPy has by far the best initial rankings
(MRR 0.55, 9--10 tasks with a reference file in the top~20) but no repair gain over \condA{}, which is
the best condition there (7 vs 6). Sphinx and pytest have the weakest rankings (MRR 0.06--0.14), yet
\condC{} resolves two more tasks than \condA{} in each. Hints change first-call viewing in every
repository, most strongly where \condA{} rarely finds the file at once (Sphinx 0 vs 6, pytest 0 vs 5 for
\condA{} vs \condC). Costs differ by repository too: Sphinx runs are the most expensive (130--160k tokens
on average), and SymPy dominates ranking time (about 23\,s per task, mostly index building).

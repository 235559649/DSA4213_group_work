\subsection*{A.3 Swing tasks}
The main-round ranking of the four conditions is decided by these seven tasks, since the other 33
have the same outcome in every condition. Two patterns stand out. First, the usual way to lose a swing
task is a regression rather than a wrong location: four of \condA's six losses are F4, where the target
tests pass but existing tests break. Second, the hint is neither necessary nor sufficient. In
sphinx-7757 the reference file is outside every hint (rank 97/110), yet \condC{} fixed it; in
sympy-18698 the file is ranked first in every hint, yet only \condA{} fixed it.

\subsection*{A.5 Stability: 8 tasks $\times$ 3 rounds}
Eight tasks were drawn before any result was seen and run three times per condition (round 1 is
the main round). Two tasks were never solved and one was always solved, so the variation comes from
the other five. Even a task solved by every condition in the main round can fail later:
sympy-24443 was resolved in round 1 everywhere, but \condB{} and \condC{} solved it only once in three
rounds. Over 24 runs per condition the totals differ by at most three (\condA{} 14 to \condD{} 17),
which is the same size as the main-round differences, so we do not rank the conditions on either
round alone. The one consistent direction is pytest-10081, which \condC{} and \condD{} solved in all three
rounds and \condA{} in one.

\subsection*{A.7 Results by repository}
Gains do not follow ranking quality. SymPy has by far the best initial rankings
(MRR 0.55, 9--10 tasks with a reference file in the top~20) but no repair gain over \condA{}, which is
the best condition there (7 vs 6). Sphinx and pytest have the weakest rankings (MRR 0.06--0.14), yet
\condC{} resolves two more tasks than \condA{} in each. Hints change first-call viewing in every
repository, most strongly where \condA{} rarely finds the file at once (Sphinx 0 vs 6, pytest 0 vs 5 for
\condA{} vs \condC). Costs differ by repository too: Sphinx runs are the most expensive (130--160k tokens
on average), and SymPy dominates ranking time (about 23\,s per task, mostly index building).

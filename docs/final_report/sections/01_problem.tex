\section*{1. Problem, Research Question, and Motivation}

An issue often describes a symptom without identifying the code responsible. In large Python
repositories, finding that code can require inspecting several files before attempting a patch.
mini-SWE-agent explores through shell commands and receives execution feedback, but its baseline
does not explicitly rerank candidate locations from that feedback.

We study localization guidance for developers and maintainers using this repair loop. An agent
is appropriate because inspection and execution provide evidence for subsequent decisions;
ranked hints can guide this process while leaving the agent free to inspect other files.

% RQ1--RQ3 retain the proposal's questions, shortened without changing their scope.
\begin{itemize}[leftmargin=*,itemsep=0.1em,topsep=0.2em]
  \item \textbf{RQ1 (repair).} Can structured repository navigation and runtime failure evidence
        help mini-SWE-agent localize relevant code more efficiently without reducing bug-fixing success?
  \item \textbf{RQ2 (cost).} Does improved localization reduce exploration cost (files inspected,
        model steps, tokens, runtime) after accounting for localization overhead?
  \item \textbf{RQ3 (signal).} What do repository structure and runtime failure evidence add
        beyond textual issue-to-code relevance?
\end{itemize}

Success requires better localization with improved repair, or comparable repair at lower
exploration cost. Repair is assessed independently by the official tests; localization gains
alone do not establish successful repair, and uncertain performance differences remain inconclusive.

\paragraph{Changes since the proposal.}
We retained 20 development tasks and reduced the planned held-out set from up to 100 to 40
under the available budget. The final limits are 250 model steps, \$3 per run and 60\,s per command,
replacing the proposed 50 steps, 30 minutes and approximately 150,000 tokens.
Development observations motivated two revisions: the hint expanded from five files to up to
20 source files with three related tests listed separately, and the structural ranking now
starts with the top-10 BM25 seeds (Section~4); both choices preceded held-out evaluation.
